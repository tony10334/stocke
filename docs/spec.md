# 主動式 ETF 觀測站 — 開發規格（v1）

> 目標：自建一個追蹤台灣主動式 ETF 的觀測網站，起步追蹤 3 檔，每日自動抓取持股與現金水位資料並累積歷史，前端以儀表板呈現。不需要 Telegram 通知。

## 1. 追蹤範圍（Phase 1）

| 代號 | 名稱 | 投信 |
|------|------|------|
| 00981A | 主動統一台股增長 | 統一投信 |
| 00403A | 主動統一升級50 | 統一投信 |
| 00405A | 主動富邦台灣龍耀 | 富邦投信 |

架構上要預留擴充空間：ETF 清單放在設定檔（如 `etfs.json`），未來加新檔只需新增設定 + 對應投信的抓取器（fetcher）。

## 2. 資料來源

### 2.1 統一投信（00981A、00403A）
- 官網每營業日 **16:30 後** 揭露「申購買回清單（PCF）」與「投資組合明細」（2026/5/12 起的公告時間）。
- PCF 內含非股票部位金額：CASH（C_NTD）、MARGIN、RP、應收處分投資款等，以及每檔持股的股數。
- **第一步任務**：用瀏覽器實際打開統一投信 ETF 專區，找到 00981A / 00403A 的 PCF 下載連結，確認格式（網頁表格 / Excel / CSV），記錄 URL 規則（是否含日期參數）。

### 2.2 富邦投信（00405A）
- 官網 ETF 投資網：`https://websys.fsit.com.tw/FubonETF/`，有「申購買回清單」專區。
- 基金頁：`https://websys.fsit.com.tw/FubonETF/Fund/Profile.aspx?stkId=00405A`
- **第一步任務**：同上，確認 PCF 頁面結構與格式（ASP.NET 網站，可能需要處理 ViewState / postback）。

### 2.3 每日行情（收盤價、淨值、折溢價、流通單位數）
- 候選來源：證交所 OpenAPI / 各投信官網淨值頁 / 聚合站（玩股網、MoneyDJ）。
- 流通單位數很重要（用於計算「每單位持股數」），通常可從 PCF 或投信淨值公告取得；若沒有，可用「基金規模 ÷ 淨值」推算。

### 2.4 備援來源（爬蟲掛掉時的降級方案）
- MoneyDJ ETF 頁（持股明細）：`https://www.moneydj.com/etf/x/basic/basic0007.xdjhtm?etfid=00981a.tw`
- 抓取失敗時記 log 並標記該日資料缺漏，不要讓整個 pipeline 中斷。

## 3. 資料模型

建議用「每日快照」為單位儲存，JSON 檔案 + Git 即可，不需要資料庫：

```
data/
  00981A/
    2026-09-15.json
    2026-09-16.json
  00403A/
    ...
  00405A/
    ...
  meta/
    prices.json        # 各檔每日收盤價/淨值/折溢價時間序列
```

單日快照 schema（示意）：

```json
{
  "etf": "00981A",
  "date": "2026-09-15",
  "source": "official",            // official | backup
  "nav": 29.30,
  "close": 29.32,
  "outstanding_units": 9498000000, // 流通單位數
  "aum": 285310000000,             // 基金規模（元）
  "non_stock": {
    "cash": 4823473398,
    "margin": 1848386338,
    "rp": 1258097300,
    "receivables": 443464120
  },
  "holdings": [
    { "code": "2330", "name": "台積電", "shares": 11864000, "weight": 10.18 }
  ]
}
```

## 4. 計算邏輯

1. **現金／非股票水位（%）** = 非股票部位合計 ÷ 基金淨資產 × 100。統一與富邦的 PCF 直接揭露現金，不需推導。
2. **每單位持股數** = 持有股數 ÷ 流通單位數。日對日比較用這個值，排除申購買回造成的規模效果（例如規模增加導致所有持股等比例增加，不算「加碼」）。
3. **持股異動偵測**：比較相鄰兩個「都有完整快照」的資料日。缺日的 ETF 不納入該區間比較（避免假訊號）。
4. **共同加碼訊號**：原站門檻是「4 檔以上共同加碼」，但 Phase 1 只有 3 檔，改為「**2 檔以上**（每單位持股數）同日加碼同一檔股票」即觸發；門檻做成可調參數，未來擴檔後再調高。
5. **公司行動偵測**：若某檔股票在多檔 ETF 中同日出現一致的倍數變化（如全部 ×10），標記為「疑似公司行動（分割/併股）待核對」，不算加減碼。
6. **個股反查**：建立反向索引 `stock → [持有它的 ETF + 最新股數/權重 + 最近一次異動]`。

## 5. 抓取排程

- 每個台股營業日 **17:30（台北時間）** 執行一次（統一 16:30 後才更新，留 buffer）。
- 建議加一次 **21:00** 的補抓：若當日資料仍缺（投信延遲公告），重試一次。
- 用 **GitHub Actions** cron 排程（免費），抓完 commit 回 repo，資料歷史自然有版本紀錄。
- 注意：GitHub Actions cron 用 UTC，17:30 台北 = 09:30 UTC。
- 判斷是否為營業日：可用簡單規則（週一至週五）+ 台股休市日清單（每年更新一次 `holidays.json`）。

## 6. 前端

- 靜態網站即可（無後端），直接讀 repo 裡的 JSON。部署到 GitHub Pages / Cloudflare Pages / Vercel 擇一。
- 技術：React + Vite（或純 HTML + Chart.js，看偏好），圖表建議 Recharts 或 Chart.js。
- 頁面區塊（參考原站，去掉 Telegram）：
  1. **總覽列**：3 檔卡片 — 收盤價、淨值、折溢價、現金水位（含日變化）、持股檔數、前三大持股。
  2. **共同加碼訊號區**：固定比較最近兩個對齊資料日，列出符合門檻的股票；下方保留最近 N 個區間的歷史紀錄。
  3. **現金水位比較**：3 檔的現金/非股票比例 + 日變化，附時間序列小圖。
  4. **個股反查（Stock Tracker）**：搜尋股票代號/名稱 → 顯示哪些 ETF 持有、權重、股數、最近異動。
  5. **單檔深入頁**：價格/淨值/折溢價走勢、現金水位走勢、持股明細表（可排序）、每日異動列表（建倉/加碼/減碼/出清）。
  6. **資料說明區**：說明資料來源、更新時間、每單位計算規則、缺日處理原則（照抄第 4 節的原則寫給訪客看）。

## 7. 開發順序建議

1. **偵察**（先做這步！）：實際打開統一與富邦的 PCF 頁面，確認 URL 規則與格式，存一份原始樣本到 `samples/`。
2. 寫 3 個 fetcher（統一 ×2 檔共用一個、富邦 ×1），輸出統一 schema 的 JSON。
3. 手動跑幾天，確認 schema 穩定。
4. 寫分析層：異動偵測、每單位計算、共同加碼、反向索引 → 輸出前端要吃的彙整 JSON（如 `site-data.json`）。
5. 前端儀表板。
6. GitHub Actions 排程 + 部署。
7. 觀察 1–2 週，處理投信延遲公告、格式變動等邊角情況。

## 8. 已知風險與注意事項

- 投信網站可能改版，fetcher 要寫得容錯（抓不到就標缺漏 + 發 log，不要寫入壞資料）。
- 兩家投信公告日期可能不同步（原站也有此問題），比較邏輯務必只用「日期對齊」的快照。
- 歷史資料從啟用日開始累積，前 1–2 週「共同加碼歷史」會很空，是正常現象。
- 尊重網站 robots.txt 與合理抓取頻率（每天 1–2 次，遠低於任何限制）。
- 資料僅供個人研究參考，非投資建議；若未來公開網站，加上免責聲明。
